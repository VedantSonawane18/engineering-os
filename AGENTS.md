# Engineering OS — Agent Instructions

## 1. Project Identity

Engineering OS is a premium interactive web platform designed to help
first-year engineering students understand:

- How college actually works
- CGPA and academic strategy
- Backlog prevention
- Programming fundamentals
- Technology roadmaps
- Development
- AI/ML
- Career preparation
- Internships
- Placements
- Practical use of AI tools

The product also hosts paid live webinars and provides long-term
educational resources.

This is a real product, not a demo or generic portfolio landing page.

---

## 2. Current Development Phase

CURRENT PHASE:

HOME PAGE / CREATIVE FRONTEND

Focus exclusively on the public-facing home page and its experience.

Do NOT implement yet:

- Backend
- Spring Boot
- PostgreSQL
- Authentication logic
- Payment processing
- Payment verification
- AI verification
- Microsoft Teams integration
- Admin dashboard
- Resource authorization
- Production deployment

These will be implemented in later phases.

## 4. Design Philosophy

The website must feel:

- Premium
- Cinematic
- Editorial
- Technical
- Minimal
- Experimental
- Sophisticated
- Human-designed

The visual quality should be comparable to strong Awwwards-style
creative websites without directly copying any particular website.

The website must NOT look like a generic AI-generated landing page.

---

## 5. Explicitly Avoid

Do not default to:

- Purple/blue AI gradients
- Excessive gradients
- Excessive glassmorphism
- Generic SaaS layouts
- Generic dashboard cards
- Excessive rounded containers
- Excessive shadows
- Stock illustrations
- Generic AI imagery
- Random 3D objects
- Excessive icons
- Excessive floating cards
- Huge collections of badges
- Unnecessary decorative elements
- Animation on every element

Avoid visual patterns that make the site resemble a
template generated by an AI website builder.

---

## 6. Color Direction

The primary visual language should be dark and restrained.

Prefer:

- Near-black backgrounds
- Off-white typography
- Muted greys
- Subtle borders
- Very limited accent colors

Color should be used intentionally.

Do not introduce bright multi-color palettes unless specifically
requested.

---

## 7. Typography

Typography is one of the primary visual elements.

Use a restrained type system consisting of:

- Display typography
- Body typography
- Optional monospace/technical typography

Typography should create hierarchy through:

- Scale
- Weight
- Spacing
- Position
- Motion

Do not use many unrelated fonts.

---

## 8. Motion Philosophy

Animation must have purpose.

Motion should communicate:

- Hierarchy
- Navigation
- Progression
- State
- Interaction
- Spatial relationships

Prefer:

- GSAP timelines
- Scroll choreography
- Subtle parallax
- Controlled cursor interaction
- Magnetic interactions
- Smooth transitions
- Restrained WebGL movement

Avoid:

- Constant floating animations
- Excessive bouncing
- Random particle effects
- Animation on every component
- Gratuitous transitions

A visitor should notice the experience,
not the animation library.

---

## 9. 3D Philosophy

Three.js / React Three Fiber should be used to create a meaningful
visual environment.

3D should reinforce concepts such as:

- Engineering
- Systems
- Progression
- Exploration
- Structure
- Technology

Do NOT add 3D merely because 3D looks impressive.

Prefer restrained abstract geometry and spatial composition over
generic 3D objects.

---

## 10. Homepage Narrative

The homepage should progressively reveal the product.

The intended narrative is approximately:

1. Introduction
2. Engineering is more complicated than students expect
3. Problems students face
4. The four-year journey
5. Academic / CGPA system
6. Technology and specialization
7. Career and placement direction
8. Webinar reveal
9. Registration CTA
10. Login / Signup

The user should feel that they are exploring a system rather than
reading a conventional landing page.

---

## 11. Interaction Philosophy

The website should respond intelligently to the user's presence.

Possible interactions include:

- Cursor-reactive 3D scenes
- Magnetic buttons
- Hover transformations
- Spatial typography
- Scroll-driven transitions
- Interactive roadmap elements
- Subtle depth/parallax

Interactions must remain discoverable and usable.

Do not sacrifice usability for visual effects.

---

## 12. Accessibility

Respect:

- Semantic HTML
- Keyboard navigation
- Focus states
- Accessible labels
- Reduced motion preferences
- Readable contrast
- Touch interaction

The creative experience must not prevent users from using the site.

---

## 13. Responsive Design

Desktop is the primary creative canvas.

Mobile must NOT simply be a scaled-down desktop.

Mobile should have its own considered composition while preserving
the same visual identity.

Heavy 3D scenes should have lighter alternatives where appropriate.

Respect:

`prefers-reduced-motion`

---

## 14. Performance

Performance is a first-class requirement.

Be careful with:

- WebGL
- Large textures
- 3D models
- Scroll animations
- Event listeners
- React re-renders
- Large dependencies

Use:

- Lazy loading
- Code splitting
- Asset optimization
- Memoization where justified
- Efficient animation loops

Do not optimize prematurely, but do not introduce obviously
expensive patterns without reason.

---

## 15. Component Architecture

Keep components small and purposeful.

Prefer separation such as:

components/
sections/
scenes/
hooks/
animations/
services/
pages/

Avoid giant files containing the entire homepage.

Separate:

- Visual presentation
- Animation logic
- Application logic
- Data
- Reusable UI

---

## 16. TypeScript

Use strict TypeScript.

Avoid:

- `any`
- unnecessary type assertions
- duplicated interfaces
- untyped props

Prefer explicit interfaces/types where they improve clarity.

---

## 17. Styling

Do not scatter arbitrary values throughout the application.

Establish reusable design tokens for:

- Colors
- Typography
- Spacing
- Motion
- Borders
- Radii

The visual system should feel consistent.

---

## 18. Code Quality

Before modifying code:

1. Inspect the existing implementation.
2. Understand the current structure.
3. Identify affected files.
4. Avoid unnecessary rewrites.

After modifying code:

1. Run ESLint.
2. Run TypeScript checks.
3. Run the production build.
4. Fix errors.
5. Summarize the changes.

Never modify unrelated working code.

---

## 19. Dependencies

Do not install a new dependency merely because it is convenient.

Before adding a dependency:

- Determine whether the existing stack already solves the problem.
- Prefer established libraries.
- Avoid redundant libraries.

Every dependency should have a clear purpose.

---

## 20. Git Discipline

Make focused commits.

Examples:

`feat: establish design system`

`feat: build homepage hero`

`feat: add cursor interactions`

`feat: add roadmap experience`

`fix: improve mobile hero performance`

Do not create giant commits containing unrelated changes.

---

## 21. Security

Never place:

- API keys
- passwords
- secrets
- private URLs
- credentials

in frontend source code.

Future payment, authentication, webinar access,
and administrative functionality must be enforced server-side.

Frontend visibility is NOT considered security.

---

## 22. Product Principle

The goal is not to make the website look impressive.

The goal is to make the user think:

"This is different."

Then:

"This understands what I'm going through."

Then:

"I want to explore this."

Then:

"I want to attend."

Design, motion, 3D, and technology must serve that progression.
